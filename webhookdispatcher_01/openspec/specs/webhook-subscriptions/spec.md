# webhook-subscriptions Specification

## Purpose

Описывает регистрацию и хранение подписчиков вебхуков — их целевой URL, секрет подписи, список интересующих типов событий и лимит исходящего RPS, — а также правило выбора подписчиков, которым адресовано опубликованное событие.

## Requirements

### Requirement: Регистрация подписки

Система SHALL принимать запрос `POST /api/v1/subscriptions` с телом JSON, содержащим `url`, `secret`, `events` (непустой массив строк — типов событий) и `max_rps`, и создавать подписку, возвращая `201 Created` с её идентификатором.

#### Scenario: Успешная регистрация

- **WHEN** отправлен `POST /api/v1/subscriptions` с телом `{"url":"https://example.com/hook","secret":"s3cr3t","events":["order.created"],"max_rps":10}`
- **THEN** система отвечает `201 Created` и телом, содержащим сгенерированный `id` подписки, её `url`, `events`, `max_rps` и признак активности

#### Scenario: Секрет не возвращается наружу

- **WHEN** подписка успешно создана
- **THEN** ответ не содержит значение `secret` ни в каком виде

### Requirement: Валидация полей подписки

Система SHALL отклонять регистрацию подписки с `400 Bad Request`, если `url` пуст или не является абсолютным HTTP(S) URL, если `secret` пуст, если `events` пуст, либо если `max_rps` меньше или равен нулю. Ответ SHALL содержать причину отказа.

#### Scenario: Некорректный URL

- **WHEN** отправлен `POST /api/v1/subscriptions` с `url` равным `"not-a-url"`
- **THEN** система отвечает `400 Bad Request` и подписка не создаётся

#### Scenario: Пустой список событий

- **WHEN** отправлен `POST /api/v1/subscriptions` с `events` равным `[]`
- **THEN** система отвечает `400 Bad Request` и подписка не создаётся

#### Scenario: Неположительный max_rps

- **WHEN** отправлен `POST /api/v1/subscriptions` с `max_rps` равным `0`
- **THEN** система отвечает `400 Bad Request` и подписка не создаётся

#### Scenario: Некорректный JSON

- **WHEN** отправлен `POST /api/v1/subscriptions` с телом, не являющимся валидным JSON
- **THEN** система отвечает `400 Bad Request`

### Requirement: Подбор подписчиков по типу события

Система SHALL адресовать опубликованное событие каждой активной подписке, чей список `events` содержит тип этого события, и не SHALL адресовать его подпискам, чей список этот тип не содержит.

#### Scenario: Событие адресовано совпавшим подпискам

- **WHEN** существуют активные подписки A (`events: ["order.created"]`) и B (`events: ["order.paid"]`) и публикуется событие типа `order.created`
- **THEN** доставка создаётся только для подписки A

#### Scenario: Нет совпавших подписок

- **WHEN** публикуется событие типа, на который не подписан никто
- **THEN** событие сохраняется, доставки не создаются, и публикация считается успешной

### Requirement: Секрет подписки используется для подписи

Каждая подписка SHALL хранить собственный секрет, который используется исключительно для расчёта HMAC-подписи её исходящих доставок и никогда не раскрывается через API.

#### Scenario: Разные подписки — разные подписи

- **WHEN** одно и то же событие доставляется двум подпискам с разными секретами
- **THEN** значения заголовка `X-Signature` в двух исходящих запросах различаются
