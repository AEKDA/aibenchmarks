# Webhook Dispatcher

Сервис доставки вебхуков: принимает события от внутренних систем, сохраняет их с
гарантией идемпотентности и доставляет подписчикам с повторными попытками,
подписью полезной нагрузки и ограничением скорости.

Текущее состояние — каркас: собирается бинарь, поднимается HTTP-сервер с
проверкой живости и корректно завершается по сигналу. Приём событий, хранилище и
доставка появляются в следующих историях.

## Требования

- Go 1.27
- PostgreSQL 18 (нужен со следующих историй, каркасу не требуется)

## Конфигурация

Все переменные окружения имеют префикс `WHD_`. Конфигурация читается один раз
при старте; при невалидном значении процесс не поднимается и печатает **все**
найденные проблемы разом.

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `WHD_DATABASE_URL` | да | — | Строка подключения к PostgreSQL |
| `WHD_HTTP_ADDR` | нет | `:8080` | Адрес прослушивания HTTP-сервера |
| `WHD_SEND_TIMEOUT` | нет | `5s` | Таймаут одной исходящей отправки вебхука |
| `WHD_LEASE_TIMEOUT` | нет | `30s` | Предельная длительность аренды попытки доставки |
| `WHD_SHUTDOWN_TIMEOUT` | нет | `15s` | Предельное время корректного завершения |
| `WHD_WORKER_COUNT` | нет | `8` | Размер пула воркеров доставки |

`WHD_LEASE_TIMEOUT` должен быть строго больше `WHD_SEND_TIMEOUT`: иначе реапер
отберёт задачу у воркера, который ещё выполняет отправку. Инвариант проверяется
при старте.

## Команды

```
make build   # сборка
make test    # тесты с детектором гонок
make vet     # go vet
make lint    # vet + проверка форматирования
make run     # запуск из исходников
```

## Проверка живости

```
curl -s localhost:8080/healthz
{"status":"ok"}
```

Эндпоинт отвечает на вопрос «процесс жив» и намеренно не проверяет внешние
зависимости — это liveness, а не readiness.

## Структура

```
cmd/dispatcher/            composition root: конфигурация, сборка графа, сигналы
internal/application/      слой домена: только stdlib и github.com/google/uuid
  entity/                  сущности и их инварианты
  errs/                    типизированные доменные ошибки
  ports/                   интерфейсы, объявленные потребителем
  instruction/             чистые переиспользуемые функции
  usecase/                 сценарии, единственный метод Invoke
internal/adapter/
  driver/                  входящие адаптеры: вызывают usecase'ы
  driven/                  исходящие адаптеры: вызываются через порты
internal/arch/             правила направления зависимостей и их тест
internal/config/           чтение и валидация конфигурации
migrations/                нумерованные SQL-миграции
```

Направление зависимостей — не соглашение, а тест: `internal/arch` роняет сборку
при импорте, нарушающем границы слоёв.
